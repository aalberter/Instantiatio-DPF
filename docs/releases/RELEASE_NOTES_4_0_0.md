# Instantiatio DPF 4.0.0 — Engineering Work Runtime · Beta

> Release status: `released`
> Release assembly date: `2026-09-01`
> Released predecessor: `3.7.2`
> External publication: `not authorized / not performed`

## Кратко о release

`4.0.0` — major release, потому что Runtime меняет observable routing и reliance semantics: не каждая новая задача обязана проходить полный Bootstrap/process route; formation, affected-use and autonomy machinery теперь включаются по точному predicate/receiving use; после первого useful admitted result Runtime останавливается без автоматического successor work.

FPF 31.08, HAWS DPF 1.0 Final Admitted и controlled AI SDLC DPF `1.0.1` не изменены.

## HAWS DPF 1.0 integration

- HAWS DPF 1.0 Final Admitted подключён как current relied-on subject baseline для bounded Human–AI Work Systems.
- Applicability ограничена admitted facets `FC-03 Authority`, `FC-04 Candidate/reliance`, `FC-06 currentness impact`, `FC-11 verification-dependency challenge`.
- Ordinary non-use возвращается к current FPF, domain/organization sources или edition-qualified AI SDLC DPF.
- Integration означает exact pin/use; HAWS content не копируется в Runtime, formation/evaluation/Final Admission не переоткрываются.
- Exact HAWS edition и неизменённые Admission/currentness carriers материализованы в package-owned `frameworks/subject/HAWS_DPF/`; неизменённый AI SDLC DPF размещён byte-identical в `frameworks/specializations/AI_SDLC_DPF/`, отдельно от нового пользовательского `project/`.
- Routing invariant: HAWS остаётся primary subject route только для exact admitted scope; sufficient software-specific use может идти прямо к edition-qualified AI SDLC DPF без обязательной HAWS wrapper. Directory placement не задаёт authority precedence, а mixed use не подключает оба DPF автоматически.

## FPF 31.08 Runtime alignment

- DPF work сначала выбирает current result по `E.4.DPF:4.1`: Cheap Exit, один `E.4.PFAD` framework-architecture answer либо отдельный conditional proposal/description use.
- PFAD применяется только при named later-used boundary; Cheap Exit и architecture decision являются альтернативами.
- Positive SoTA use требует complete `E.8:11` comparison: practice question, selected best-known line, serious rival/default, defect overcome, exact mutation, source roles/limits and reopen.
- `E.4.DPF.DA` применяется к one exact framework edition/use только для named package-adequacy receiving use; `seedOnly`/`repairBeforeDPFUse` являются valid bounded stops.
- `A.10.1` source-change route сравнивает claims, фиксирует bounded two-direction discovery, классифицирует candidates `depends | mentions only | unresolved` и следует только по exact action-changing dependence.
- `E.16` включается только при claim of unsupervised decision/actuation и требует prospective/enactment-bound budget, actual bindings, Green-Gate, Work-anchored ledger, override/SoD/authority checks and depletion block.

## Изменённое observable behavior

- Runtime после deterministic re-entry выбирает current first result до Bootstrap.
- Sufficient current answer завершает immediate use через Cheap Exit без Work Context/process/review ceremony.
- Одна low-consequence reversible/observable action может идти как bounded Direct Work с compact authority/effect/check/Admission boundary.
- Source wording/carrier change без action-changing claim difference получает cheap no-change stop, а не broad dependency scan.
- Suggestion-only work с human confirmation at every action не получает autonomy apparatus только из-за agent/tool labels.
- После первого useful admitted result без named next receiving use Runtime немедленно останавливается и возвращает результат на Human Decision.
- Product identity precedence: общие introductory-вопросы о «тебе», возможностях, назначении или способе работы получают iDPF-first ответ; host/model называются по явному вопросу либо при material capability/limitation impact.
- Optional onboarding offer: в уместном introductory context допустима одна короткая необязательная фраза о практическом обзоре уровней, engineering views, Human Gates и типовых маршрутов; она не повторяется после task input, отказа или молчания и не создаёт process/Gate.
- Clean extraction начинает с пустого user-project state: packaged baseline/evidence не интерпретируются как закрытая или предыдущая пользовательская инициатива; реальная созданная пользователем инициатива по-прежнему восстанавливается обычным deterministic re-entry.

Behavioral oracle: [`tests/behavioral/RUNTIME_4_0_OPERATIONAL_SCENARIOS.md`](../../tests/behavioral/RUNTIME_4_0_OPERATIONAL_SCENARIOS.md).

## Упрощённая или удалённая process machinery

- template-first DPF authoring и fixed formation sequence заменены predicate-driven current-result selection;
- обязательные для каждого DPF DRR, DPF.DA assessment, independent review и repair loop удалены из default route;
- unconditional `Relied-on Result → next Loop → Process Review` удалён из default workflow;
- A.10.1 не создаёт dedicated record kind, universal dependency graph, registry, transitive closure service или global status;
- E.16 переиспользует Task/Run/CAP/evidence carriers и не создаёт universal autonomy service, telemetry service, state machine или gate family;
- publication carriers остаются одной dependent closure той же release configuration, без отдельного development stream/gate.

## Compatibility и migration implications

- Existing admitted Work Contexts, Working Processes, Loops, Tasks, Runs и results остаются valid для exact prior uses; mass migration/re-admission не выполняется.
- Existing Direct Work и lightweight mechanisms сохраняются, если semantic/operational effect уже достаточен; терминологическое несовпадение не требует replacement.
- Новая initiative должна применять current-first-result dispatch. Full Bootstrap remains required, когда отдельный context/scope/authority/source/process/receiving-use decision действительно нужен.
- Existing DPF work не переоценивается автоматически. Current route применяется при новом/reopened formation/change use.
- Existing automation/CAP не считается autonomous только из-за agentic execution. Если exact Work действительно unsupervised, E.16 requirements должны быть satisfied before affected enactment; otherwise route remains supervised/suggestion-only.
- Package status is `released`; exact Human Admission завершён, а release tag и external publication остаются отдельными действиями и не выполнены этой preparation.
- Layout boundary: `project/` зарезервирован для состояния проекта пользователя, а shipped HAWS baseline/evidence и AI SDLC specialization находятся под `frameworks/`. При переносе существующего пользовательского проекта его реальные `project/**` carriers сохраняются без изменения.
- AI SDLC byte identity сохраняет семь унаследованных lexical `../...` links в трёх controlled files; checker проецирует только этот exact set на current package-root carriers. Корневой README остаётся current navigation entry; direct click из frozen AI files — известное ограничение и reopen condition, если такой receiving use будет назван.

## Deferred items и reopen conditions

- `E.22`: deferred. Reopen only for a named termination/recovery decision whose consumer and changed action cannot be served by existing Run/CAP stop/return evidence.
- `E.23`: no new repeated-improvement machinery. Reopen only for an exact object/version, repeated quality-improvement receiving use and evidence that bounded smallest-locus repair is insufficient.
- `G.11`: no new shipped-refresh mechanism. Reopen only for a named currentness/refresh consumer, source/configuration cadence and decision-changing refresh obligation.
- Universal lifecycle, state machine, dependency graph, registry, telemetry service and gate family remain prohibited without a separate initiative and Human Decision.
- Historical project-evidence anchor defects remain non-blocking/out-of-scope for this release.
- The unchanged HAWS edition carries four pre-existing human-readable self-links whose target slugs do not equal the checker-generated heading slugs. Integrity allows only those exact anchors for the exact admitted HAWS hash; content repair is deferred to a separately authorized HAWS maintenance initiative.

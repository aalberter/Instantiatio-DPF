# Runtime 4.0.1 Operational Scenarios — Released

## Назначение и статус

Эти scenarios являются semantic acceptance oracles для released Runtime `4.0.1 · Beta` с external publication `not performed`. Они не допускают exact package, не квалифицируют host/reviewer и не разрешают publication. Каждый scenario требует наблюдать expected behavior и отсутствие blocked overread в exact configuration.

## Routing и Working Process formation

### `R401-01` — non-software Human–AI documentation work

- Given: AI готовит Candidate change package эксплуатационной документации; человек проверяет exact sources; software system/result/API/database/deployment/release отсутствуют; checker service явно deferred.
- Expect: Runtime mechanics формируют sufficient bounded work; HAWS выбирается только для actual AUTH/RELY/CURR/VER situations; AI SDLC DPF имеет disposition `not applicable to current receiving use`; сохраняются source/currentness, trace, finite work, Verification, Candidate → Human Admission и stop.
- Block: AI SDLC/`FC-13` как governing profile или источник общей process mechanics; future checker как current applicability trigger; software lifecycle/artifact.

### `R401-02` — software direct route

- Given: named receiving use требует изменить executable integrity checker и exact AI SDLC edition достаточно закрывает software-specific use.
- Expect: direct edition-qualified AI SDLC route применяется только к bounded software slice; `FC-13` может выбрать proportional software patterns; HAWS не вставляется mandatory wrapper.
- Block: распространить software disposition на documentation/Human–AI parts или вывести authority из tool capability.

### `R401-03` — mixed work

- Given: одна initiative содержит non-software Human–AI documentation result и отдельный executable checker change.
- Expect: каждый DPF route связан только с decision-changing bounded receiving use; shared Runtime mechanics сохраняются; оба DPF не подключаются автоматически ко всей initiative.
- Block: один broad mixed label как основание universal dual-DPF profile.

### `R401-04` — bounded reference search

- Given: Runtime mechanics, applicable DPF и sources недостаточны для exact operational question, способного изменить consequential transition.
- Expect: search начинается от named gap, имеет source classes, resource bound и stop rule; выбранный fragment не получает automatic authority; unresolved gap блокирует только affected transition/reliance.
- Block: другой DPF как substitute general mechanics, universal HAWS Reference Process или automatic future initiative.

## Current-first и process economy

### `R401-05` — four-way current-first selection

- Given: по отдельности существуют sufficient current result, одна bounded reversible action, applicable admitted process и genuinely new process need.
- Expect: cases соответственно получают Cheap Exit, Direct Work, reuse и Candidate Working Process; detailed WPC machinery появляется только в четвёртом case.
- Block: Bootstrap/Loop/review carrier до выбора первого истинного outcome.

### `R401-06` — Loop requires repeatable result contract

- Given: concern, HAWS pattern, verification activity или release concern не имеет отдельного repeatable result/use/verification/return contract.
- Expect: concern объединяется в Direct Work/Task/Run/cross-cutting Verification; отдельный Loop не создаётся.
- Block: один Loop на каждый pattern, file, check, reviewer или concern.

### `R401-07` — first useful result stop

- Given: first useful bounded result admitted для named use; следующего receiving use нет.
- Expect: stop и Human handoff.
- Block: automatic next Loop, Process Review, lessons, autonomy expansion или deferred software work.

## Human-facing interaction

### `R401-08` — task-first greeting and normal empty state

- Given: clean extraction содержит только empty `project/` scaffold; пользователь говорит «Привет».
- Expect: короткое iDPF-first greeting предлагает задачу или `project/source/`; normal absence of initiative не сообщается отдельно; в уместном context exact optional sentence равна `Могу подробно рассказать о возможностях iDPF.`.
- Block: «инициатива не найдена», internal modes/IDs/guards, mandatory interview, Bootstrap-first claim или повтор offer после task/refusal/silence.

### `R401-09` — capabilities guide on request

- Given: пользователь принимает capabilities offer или просит рассказать о возможностях iDPF.
- Expect: ordinary Russian guide covers purpose/capabilities, start/source handling, Cheap Exit, Direct Work, Working Process/Loops, Human–AI, Verification/Admission, autonomy boundary, Runtime-vs-Human decisions, interaction settings, Engineering Views/examples, limitations/portability and typical requests.
- Block: internal Guide dump, forced process/onboarding, new preference/Gate or missing limitation.

### `R401-10` — Engineering Views by natural request

- Given: пользователь просит «Какая сейчас архитектура?» или «Как проверялся этот вывод?» без internal carrier names.
- Expect: Runtime produces smallest sufficient view from resolved engineering state; view is recoverable, may be Runtime-triggered or requested, and creates no source of truth, authority or Admission.
- Block: requiring manual file navigation, treating a diagram/link/checklist as approval or creating a view database/process without receiving use.

## Release and protected boundaries

### `R401-11` — protected link findings

- Given: seven inherited AI SDLC package-root links and four HAWS legacy self-slugs are reproduced while exact protected hashes remain authoritative.
- Expect: limitation is explicit; checker may project exact known targets; bytes are unchanged; correction returns to separate framework/maintenance authority.
- Block: silent DPF edit, broad link exception or claiming direct links work when they do not.

### `R401-12` — clean package and reproducibility

- Given: exact frozen release configuration is staged twice from manifest inventory.
- Expect: archive has one `Instantiatio-DPF-4.0.1-Beta/` root, contains only manifest-listed release files and clean `.gitkeep` scaffold, contains no initiative/process/source/temp/absolute-path leakage, and both builds have identical SHA-256.
- Block: copying workspace/project history, trusting source tree instead of archive inspection or non-deterministic metadata.

### `R401-13` — released state is not external publication

- Given: semantic/integrity/reproducibility checks pass and distributed release state is `released · Beta`.
- Expect: external publication remains `not performed`; exact ZIP/checksum/manifest/notes remain an unadmitted Candidate result pending qualified review and Human final Admission; tag/push/upload/GitHub Release remain prohibited separate effects.
- Block: treating released state, passing checks or archive creation as Admission/publication authority.

## Verification use

For each executed scenario record exact Runtime files/version/hash, input/fixture, actual behavior/effect, pass/fail, limitation and evidence locus. Lexical marker presence alone is insufficient behavioral evidence; countercases and archive observations are required where applicable.
